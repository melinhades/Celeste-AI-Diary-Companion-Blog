Celeste 鸟的运动逻辑 · JS 复刻

按 Celeste.dll 的 IL 逐行还原的三条管线：FlutterBird（贝塞尔弹跳 + 速度积分惊飞）、BirdPath（协程只写 target，Update 做物理追赶）与 BirdNPC（会喊叫、啄地、举教程面板、被你靠近就飞走的那只）；外加拦住它的 Lightning 电网与给它供电的 LightningBreakerBox 电闸（冲刺两下砸开）。协程用帧驱动生成器实现，所以 yield null = 下一帧、yield 0.25 = 等 0.25 秒，与 C# 的 Coroutine 语义一致。鸟的贴图用的是仓库自带的原版图集（Atlases/Gameplay/ 与 Atlases/Gui/），动画表、锚点、染色、面板同样抄自 Sprites.xml 与 IL。

怎么玩

  • 鼠标就是 Player。把它移到站立鸟的左边或右边：水平差 < 48px，且 mouse.Y ∈ (鸟.Y-40, 鸟.Y+8) → 惊飞，并且连锁传给 48×48 方框内的同伴。
  • 勾选 inVanilla 并把 speedMult 拉到 3：目标点跑得比物理上限还快 3 倍，鸟明显追不上自己的路径 —— 这就是 Everest 在 IL 层修的那个 bug。
  • speedMult 拉低到 0.2 并关掉 angleFix：target 会落到鸟身后，两个角度互相抵消，鸟开始侧身 90° 飞。打开 angleFix 就正常了。
  • 右上角「暂停」冻结时间；C# 里 yield return <float> 按 DeltaTime 递减，所以慢动作/暂停会一起变慢。
  • BirdNPC 靠距离驱动：把鼠标放到 FlyAway 那只的水平 120px 内 → 先喊一嗓子（croak），再靠到中心距 32px 内 → Startle 撒羽毛 + 飞出屏顶。每只鸟盯的距离都不一样，勾上「调试」就能看到各自的阈值框。
  • 按住鼠标 = Player.StateMachine.State == 1（挂在墙上爬）。放到 Climbing 那只旁边按住，它的面板会真的翻到背面（tutorial_note_flip_back），松手爬过头再翻回来。
  • URL 参数可以直接分享某个判定瞬间：?px=600&py=436 把“玩家”摆到坐标上，&down=1 表示按住（爬墙），&invincible=1 打开辅助模式 Assists.Invincible（会换掉 Dashing 那只的触发窗口）。
  • 声音是本体：待机鸟从出生就挂着一个 SoundSource 循环啾啾（birdbaby_tweet_loop），每跳一下先一声 birdbaby_hop，被你靠近就 Stop(true) 换 birdbaby_flyaway。素材在 celeste-sounds/Birds/，事件名全部来自 IL；浏览器不允许无手势自动播放，所以点一下页面才会听到。音量按离玩家的距离衰减，?sfx=0 可关。
  • 电闸（LightningBreakerBox）：同时勾上「Lightning」与「键盘模式」，用 X 朝电闸冲刺两下就能砸开：第一下压扁贴图 + 抖 + 冻结 0.1s + 开始冒火星，0.2s 后「开箱」；第二下爆掉、冻结 0.2s、冲刺次数被重置，整屏电网跟着 Shatter（这就是电网消失的入口）。
  • 「贴图倍率」只放大鸟本身，不放大世界：物理常量（48px 接近框、14px 控制点）仍按游戏原尺寸 1px = 1px 算。FlutterBird 真的只有 10×10 像素（原版它就是 scenery），拉到 3× 以上才能看清翅膀。

FlutterBird：逐行对应的常量

待机 IdleRoutine                          惊飞 FlyAwayRoutine
  delay   = 0.25 + NextFloat(1)             yield delay                       // 秒，不是帧
  等待期每帧检查玩家接近框                     play "fly"
    |player.X - X| < 48                     scale   = (-dir*1.25, 1.25)       // 起飞拉伸
    player.Y ∈ (Y-40, Y+8)                  弹射 to   = Pos + (dir*4, -8)      // 位移量
    命中 → FlyAway(Sign(dx), NextFloat(.2))   进度 p += dt * 3                 // ≈0.33s
  落点    = start + (-4 + NextFloat(8), 0)   翻身   scale.X = -scale.X
  控制点  = 中点 + (0, -14)  → 峰值仅升 7px    初速度 v   = (dir, -4) * 8
  进度    p += dt * 4      → 一跳 0.25s        加速度 a   = (dir*64, -128)      // px/s²
  落地    scale = (±1.4, 0.6)                  连锁  OnInterval(0.1) 且 48×48 方框
  Position 由协程直接写                    离场  Y+8 < Bounds.Top → Remove

回弹（Update，定速不是插值）
  scale.X = Approach(scale.X, Sign(scale.X), 4*dt)
  scale.Y = Approach(scale.Y, 1,             4*dt)

FlingBird：抱住 → 甩出 → 逐节点 relocation → 等电网清空（第三把管线）

它和 BirdNPC 是两个不同的实体（BirdNPC 只负责说话/举面板，Modes.WaitForLightning 在 IL 里根本没有分支）。

States（FlingBird/States）   Wait=0  Fling=1  Move=2  WaitForLightningClear=3  Leaving=4

每帧 Update（顺序就是 IL 顺序：base.Update() 先跑，所以协程、Sprite、PlayerCollider 都在 switch 之前推进）
  if (state != Wait) sprite.Position = Approach(sprite.Position, spriteOffset, 32*dt)   // 贴图回中
  Wait:  p.X - X ≥ 100(SkipDist) 或 (SegmentsWaiting[segmentIndex] && LightningRemoved) → Skip()
         amount = ClampedMap(|p.Center - Position|, 16, 64, 12, 0)
         sprite.Position = Approach(sprite.Position, spriteOffset + SafeNormalize(dir) * amount, 32*dt)
         ⇒ 玩家越近，贴图被推离本体越远，而本体一动不动 —— 不是躲，是怕
  Fling: if (flingAccel > 0) flingSpeed = Approach(flingSpeed, flingTargetSpeed, flingAccel*dt)
         Position += flingSpeed * dt          // ★ 整个甩出的位移只由这一句产生，协程从不写 Position
  Move:  空分支 —— 位移全在 MoveOnCurve 协程里直接写 Position
  WaitForLightningClear: 房间里没有 Lightning 了（或已越过 Bounds.Right）→ Leaving + LeaveRoutine()

抓取判定在 Player 那一侧（全程序集 PlayerCollider::Check 的唯一调用点，IL_1110..IL_11b6）：
  if (!Dead && State != 21) { Collider previous = Collider;  Collider = hurtbox;   // ★★ 临时换成受击盒
      foreach (pc in Scene.Tracker.GetComponents<PlayerCollider>()) { if (pc.Check(this)) {…} }
      if (Collider == hurtbox) Collider = previous; }
  ⇒ 用来撞鸟的是 normalHurtbox = Hitbox(8, 9, -4, -11)（中心 = Position + (0, -4.5)），不是 normalHitbox(8, 11, -4, -11)；
  ⇒ 遍历由 Player 每帧驱动，PlayerCollider 自己没有 Update；FlingBird 的两个 collider 参数都是 null
    ⇒ 走「直接 p.CollideCheck(entity)」分支，命中半径是鸟的 Circle(16, 0, 0)。

OnPlayer(Player p)（只在 Wait 生效，返回值决定能不能抱）：
  if (state == Wait && p.DoFlingBird(this)) {
      flingSpeed = p.Speed * 0.4; flingSpeed.Y = 120;   flingTargetSpeed = Zero; flingAccel = 1000;   // 先跟着玩家往下
      p.Speed = Zero;  state = Fling;  Add(new Coroutine(DoFlingRoutine(p), true));   // ★ 协程挂在鸟自己身上
      Audio.Play("event:/new_content/game/10_farewell/bird_throw", Center); }
  Player 侧：DoFlingBird 里 State = 24（+ 丢下手里的东西），抱期间每帧被拎到
      (bird.X, bird.Y + 8 + Collider.Height) = 鸟下方 19px，定速 250*dt；
      FinishFlingBird() 把 Speed 交还成 (380, -100)（FlingBird.FlingSpeed 是 static）。

DoFlingRoutine 的时间线（每一步都是 IL 里的字面量）：
  camPt = p.Position - Camera.Position，X 夹到 [145, 215]、Y 夹到 [85, 95]
  Add(Coroutine(level.ZoomTo(camPt, 1.1, 0.2), true))   // 焦点与 ZoomTarget 瞬变，只有缩放值走 SineInOut
  Engine.TimeRate = 0.8   →   Input.Rumble(0, 1)   →   while (flingSpeed != Zero) yield null
  play("throw")；scale.X = 1；flingSpeed = (-140, 140)、target = Zero、accel = 1400   // 先弹一下
  yield 0.1   →   Celeste.Freeze(0.05)   →   target = FlingSpeed、accel = 6000   →   yield 0.1
  Input.Rumble(2, 1)   →   Engine.TimeRate = 1   →   level.Shake(0.3)   →   Add(Coroutine(level.ZoomBack(0.1), true))
  p.FinishFlingBird()   →   target = Zero、accel = 4000   →   yield 0.3   →   Add(Coroutine(MoveRoutine(), true))

MoveRoutine：play("fly")、scale.X = 1、bird_relocate，节点成对消费（i += 2，i 是控制点、i+1 是落点）
MoveOnCurve(from, anchor, to)：curve = SimpleCurve(from, to, anchor)   // 参数序是 (begin, end, control)
  duration = curve.GetLengthParametric(32) / 500            // 500 px/s，比 BirdPath 的 150 快得多
  t 从 0.016 起、每帧 += dt/duration；Position = Floor(curve.GetPoint(t))
  rotation = Angle(GetPoint(max(0, t-0.05)), GetPoint(min(1, t+0.05)))    // 前后各 5% 的割线当切线
  scale = (1.25, 0.7)                          // 飞行时被压扁
  离上一节 > 32px 时 TrailManager.Add(this, #639bff, 1)   // 与 BirdPath 同一个色，因为同一个字段

★ 时间层（全部来自 Engine::Update IL_009a..IL_0183）：
  DeltaTime = RawDeltaTime × TimeRate × TimeRateB × GetTimeRateComponentMultiplier（后者无覆写者⇒恒 1），
    而且是在帧首算的 ⇒ TimeRate = 0.8 要到下一帧才生效（实测：FinishFlingBird 交还 380 的那一帧，
    NormalUpdate 仍按 0.8 结算，水平只掉 400×0.65×(1/60×0.8) = 3.47）。
  Entities.UpdateLists() 排在 freeze 判定之前 ⇒ 定格那几帧 Add/Remove 照样提交，只是没人 Update。
  FreezeTimer > 0 时整帧只跑 scene.FreezeFrameUpdate()，而它只遍历 this[TagsExt.FreezeFrameUpdate]；
    全程序集搜这个标签的引用点只有 4 个（Engine::Update / Scene:: / Level:: / Tags::Initialize），
    没有任何实体给它赋过值 ⇒ Freeze(0.05) 的三帧里整个场景一个 Update 都不跑：
    TimeActive 不推进、震动既不重算也不衰减、flash 不回落、协程不推进。倒计时用的是 RawDeltaTime。
  协程是 Component 且全部 Entity::Add 在实体自己身上 ⇒ 实体 RemoveSelf()，它的协程跟着消失；
    所以有宿主的协程不在全局阶段跑，而是跟着宿主 base.Update() 里的 Components.Update() 被推进。
★ 入场层（EntityList::Add / UpdateLists IL_0037..IL_006d）：是「加一个、立即 Awake 一个」，不是一批批。
  而 FlingBird::Awake 的合并只在 all[0] === this 那只身上发生 ⇒ 必须让右边那只先入场，
  最左那只 Awake 时才看得见它，两段才会并成一条链。按 X 从小到大入场的话，两只鸟永远各自只有一段，
  观感一样、但永远不会有 relocation。
★ FlingBird::Update 的 switch 之后没有任何代码（四个分支都以 ret 收尾），所以调试 HUD 只能放在 switch 之前。
★ 玩家死亡：原版是从 Session.RespawnPoint（ChangeRespawnTrigger::OnEnter 写、LevelLoader 读）重新进房；
  本页没有房间数据，“原地复活”那一帧必须立即同步到指针位置，否则还停在致死格上会被当场再杀一次。

Lightning：电网是怎么把鸟按住的

构造：Collider = Hitbox(VisualWidth - 2, VisualHeight - 2, 1, 1)（比视觉小 2px、内缩 1px）
      + PlayerCollider(OnPlayer, null, null)；有节点就挂 MoveRoutine（SineInOut 来回，永不停）；
      toggleOffset = Calc.NextFloat()   // 每根的相位不同，所以不会整屏一起闪
Update：base.Update() 在最后；Collidable 时每 onInterval(0.25, offset) 复查一次，不 Collidable 时提速到 0.05
InView：用 Camera（不是 viewport）的 320×180 ± 16px；Visible = Collidable = InView()
OnPlayer：非消散中且 !Assists.Invincible → p.Die(UnitX * (Sign(p.X - X) 或 -1))
d__21：屏幕外的先 RemoveSelf → 停氛围音、冻结种子 → t += dt*4 爬到 1（Glitch/Bloom/Fade）
      → level.Shake(0.3) → 倒序逐根 Shatter（8px 网格发射 P_Shatter）→ t += dt*8 回落到 0
      → 全部 RemoveSelf → FindFirst<FlingBird>().LightningRemoved = true   // ★ 只标第一只
      ⇒ 电网没清空的段 hoverStressed 且面朝右；清空后 Skip()（= 直接进 Move，不是删除）。

SpeedRing（launched 的唯一可见结果，每 onInterval(0.15) 撒一枚）：
  寿命正好 1/3 秒（lerp += 3*dt），沿发射法线飘 10px/s，颜色 Alpha 从 0.6 线性褪到 0；
  原版先渲染进 GameplayBuffers.SpeedRings 这张 4×4 槽位（每格 64）的离屏图，再进 Bloom 链；
  圆环半径 4→14，但被法线压扁：r * Lerp(r, r*0.5, |dot(dir, normal)|)，正对方向最扁，16 段中心对称。

LightningBreakerBox：两下冲刺砸开电闸，电网整屏碎掉

电网的电源。原版是 Farewell 里那个 32×32 的 breakerBox：Solid、health = 2，
冲刺（dash）撞两下就炸，炸的时候调用 Lightning::RemoveRoutine 把整屏电网一起拆掉 ——
所以它同时也是「电网是怎么消失的」的入口。

构造（.ctor(Vector2 position, bool flipX)，IL_0000..0122）
  base(position, 32f, 32f, true)            SurfaceSoundIndex = 9（走金属音）
  start = Position                                // 快照，Update 每帧从这里重算，只读
  sprite = SpriteBank.Create("breakerBox")；Sprite.Position = Size/2 = (16,16)；FlipX = 实参
  SineWave(0.5, 0) + Wiggler.Create(1, 0.5, null, false, false)（StartZero=false）+ Shaker(false, null)
  OnDashCollide = Dashed                          // Platform 的委托，由 Player::OnCollideH/V 派发
另一个重载 .ctor(EntityData, Vector2) 只读四个属性：flipX / flag / music / music_progress / music_session。

Awake：Position ∓ UnitY / UnitX 各探一次 Spikes（spikesUp/Down/Left/Right）
Added：flag && Session.GetFlag("disable_lightning") → RemoveSelf（本页 flag 恒 false）

Dashed(Player p, Vector2 dir)：返回值只有两种
  ① 该方向贴着尖刺 → NormalOverride（让玩家被尖刺正常扎死，而不是砸箱子）
  ② 其余一律 → Rebound（IL_01c9 的 ldc.i4.0 是唯一出口）
  DirectionalShake(dir, 0.3)
  sprite.Scale = (1 + |dir.Y|*0.4 - |dir.X|*0.4, 1 + |dir.X|*0.4 - |dir.Y|*0.4)
      ⇒ 正面撞压成 (0.6, 1.4)、侧面撞拉成 (1.4, 0.6)，随后被 Update 末尾的 Approach 弹回 1
  health -= 1
  if (health > 0)   // 第一下
      firstHitSfx = new SoundSource("…/fusebox_hit_1") + Add；Celeste.Freeze(0.1)
      ShakeCounter = 0.2；Shaker.On = true；bounceDir = dir；Wiggler.Start()；SmashParticles = true
      Pulse()；Input.Rumble(1, 1)
  else              // 第二下：爆
      firstHitSfx.Stop(true)；Audio.Play("…/fusebox_hit_2", Position)；Celeste.Freeze(0.2)
      p.RefillDash()（★ 砸开电闸顺手把冲刺还给玩家）；Break()；Input.Rumble(2, 2)
      SmashParticles(Perpendicular(dir)) 与 -(…)：两簇

Pulse()：不是「自己闪」，而是 Add(new Coroutine(Lightning::PulseRoutine(Level), true))
  → SetPulseValue 把 Glitch.Value → 0.075、Bloom.Strength → 1.2 再回落（和 Break 的 0.15 / 1.5 是两套数字）

Break()（IL_0000..0174，顺序就是 IL 顺序）
  RumbleTrigger.ManuallyTrigger(Center.X, 1.2)；Tag = Persistent
  ShakeCounter = 0；Shaker.On = false；sprite.Play("break")；Collidable = false；DestroyStaticMovers()
  flag → Session.SetFlag("disable_lightning", true)
  music / music_progress / music_session 三支（改 AudioState.Music 的事件与进度）
  pulseRoutine.Active = false
  Add(new Coroutine(Lightning::RemoveRoutine(Level, RemoveSelf), true))   ⇒ 整屏电网一起 Shatter
      ⇒ 拆完 FindFirst<FlingBird>().LightningRemoved = true，那只鸟才肯 Skip

Update()（IL_0000..022f，base.Update() 在第一行）
  makeSparks && onInterval(0.03) → Emit(P_Sparks, 1, Center, One*12)
  ShakeCounter > 0：减 DeltaTime；≤0 那一帧 → Shaker.On=false、sprite.Scale = One*1.2、play("open")
  Collidable 时：sink = Approach(sink, Rider?1:0, 2*dt)；SineWave.Rate = Lerp(1, 0.5, sink)
      at = start 的副本；at.Y += sink*6 + sine.Value * Lerp(4, 2, sink)
      at += (bounce.Value * bounceDir) * 12          // Wiggler 的弹动，方向就是被撞的方向
      MoveToX/MoveToY(at)；SmashParticles 标志一置位就发两簇
  末尾：Scale 两分量各自 Approach(…, 1, 4*dt)；LiftSpeed = Zero
  ★ at.Y 改的是 start 的局部副本（IL_0105..010b 先 ldloc 拷贝），所以 start 不被污染、不会累积漂移。
Render()：sprite.Position 临时 += Shaker.Value，画完再还原（所以抖动只动贴图、不动判定框）。

SmashParticles(dir)：四向各一套锚点/抖动范围/角度，count 统一 +2
  dir = +X   angle 0        at = CenterRight - UnitX*12   range = UnitY*(H-6)*0.5   count = (32/8)*4 + 2 = 18
  dir = -X   angle π        at = CenterLeft  + UnitX*12   range = UnitY*(H-6)*0.5                18

控件行四种类型（宽度算法取自 UpdateControlsSize 的 IL）：
  string            measureText(文本)，不加 padding；渲染时双绘：+2px 主题色 #6179e2 当阴影、-2px 白
  ButtonPrompt      guiButton(Dash|Jump|Grab|Talk) 的贴图宽 + buttonPadding*2（= 8*2）
  Vector2           固定 72 + buttonPadding*2，贴图是 controls/directions/<x>x<y>.png
  MTexture          用 texture.Width（比如 GFX.Gui["tinyarrow"] 的 30，不加 padding）
实测宽：图面板 240 + 64 = 304；文字面板 h = 24 + 24 + 32 = 80。
MTexture.Draw(pos, origin, color, scale) 的第二参是 origin 不是偏移，
origin = (-cpX, Height/2) → top-left = pos - origin*scale，控件行以 p.Y 为垂直中心。

class SimpleCurve {                      // 字段顺序 (Begin, End, Control)，二次贝塞尔
  getPoint(t){ const u = 1-t;
    return { x: u*u*this.p0.x + 2*u*t*this.c.x + t*t*this.p1.x,
             y: u*u*this.p0.y + 2*u*t*this.c.y + t*t*this.p1.y }; }
  getLengthParametric(res = 32){          // ≈ 把 [0,1] 均分 res 段的折线长
    let prev = this.getPoint(0), len = 0;
    for (let i = 1; i <= res; i++){ const p = this.getPoint(i/res);
      len += Math.hypot(p.x-prev.x, p.y-prev.y); prev = p; }
    return len; }
}
angleDiff(a, b)   // 把 b-a 折到 (-π, π]
angleLerp(a, b, p) = a + angleDiff(a, b) * p
angleApproach(v, t, maxMove)             // 定速转过去，用 Clamp(diff, -maxMove, maxMove)
approach(v, t, maxMove)                  // 定速逼近，不过冲
safeNorm(x, y, len)                       // 零向量返回零，不返回 NaN
easeCubeOut(t) = 1 - (1-t)³               // Ease.Invert(CubeIn)
