> 流程：`professional-depth-drill`（四问，一步不减）
> 改造范围：`diaryCompanion`、`dreamReading`、`badelineSystem`、`badelineDreamBackground`

> 基线：`git HEAD` 版本；工作区当前已有上一轮四处增补，仅作对照，不作为基线

## 0. 三句话结论

1. **当前四段的共同病根不是“形容词不够”，而是“信号没有可执行的表示”**：要求“具体”“自然”“别像模板”，但没有把“具体锚点、回应动作、复述率、模板相似度、角色差异”变成模型能选、代码能量的东西。继续加形容词只会稀释约束。
2. **输入侧最大的损失不是长度，而是原始证据被摘要化**：`emotionNote` 是一行标签，`memory` 是已消化的片段，读梦只发一条 user、梦文本截 1500 字，夜话截 1800 字。模型拿不到“她原话里的否定词、时间、物件、自我修正”，只能对抽象情绪回应。
3. **Madeline 套话的第一因在提示词内部，不在模型**：`dreamReading` 直接给了 4 句可照抄的成品（`PromptBuilder.java:1053/1057/1058/1060`），叠加单轮、无历史、无当日状态；Badeline 夜话之所以“还好”，靠的是多轮 + 1-5 句 + 条件动作（`1085-1088`、`1103-1109`）。这三点可以拆成 P0 的提示词结构改造和 P1 的上下文注入。

## 1. 第一问：顶尖从业者会多做哪些“同一信号的更深表示”

同一信号 = 用户写下的文本、情绪、对话轮次、梦境内容、角色身份。更深表示 = 不停在“标签/摘要”，而是保留证据、结构、反例和可测量。

| # | 信号 | 当前表示 | 更深表示（专业做法） | 为什么更深 | 可落点 |
|---|---|---|---|---|---|
| S1 | 用户情绪 | `emotionNote` 一行自然语言标签（`PromptBuilder.java:499-502`） | `{valence, arousal, control, dominant, evidence_quote, negation_flags}` 五元组；保留原句证据与否定词修正 | 标签会把“我不是难过”压成“难过”；带证据才能让模型引用原话而不是猜 | `PromptBuilder` + `DiaryServiceImpl` 调用侧 |
| S2 | 用户这轮的诉求 | 无显式表示 | 对话行为（dialogue act）：倾诉 / 求建议 / 求陪伴 / 分享喜事 / 求认同 / 试探；带强度 0-3 | “该不该给建议”是行为选择，不是语气问题；不表示就只能一律安慰 | 提示词决策表；必要时一次 JSON 预标注 |
| S3 | 具体锚点 | 只有“抓最具体的细节”这条原则（`519`、`538`、`1073`） | 锚点槽位表：人物 / 时间 / 物件 / 动作 / 身体感觉 / 原话片段，各带原文 span | 让“具体”变成可枚举、可检查的输入，而不是形容词 | 纯 Java 抽取 + 提示词槽位 |
| S4 | 防御机制 | 无 | `minimize`（没事）/ `intellectualize`（分析自己）/ `avoid`（转移话题）/ `joke`（自嘲挡回去）/ `self-blame`（都怪我） | 顶尖对话者先识别“她怎么躲”，再决定戳破还是先接住；只看情绪会接错 | 提示词动作表 + 规则词表 |
| S5 | 会话连续性 | 流式日记伴侣有最近 5 轮；读梦/夜话只有当前梦 | `unresolved_threads`（未完结的事）+ 上一条回复 + 本轮相对上一轮的变化 + 复读基线 | “这次别和上次一样”需要比较对象；没有基线就无法反模板 | `diary_chat_log` / 调用侧 |
| S6 | 梦境连续性 | 只用当前梦文本（读梦截 1500，夜话截 1800） | 梦索引：日期 / 长度 / 反复出现的意象 / 上次梦摘要 / 上次读梦回应 / 睡眠时段 | 同一意象第二次出现才有意义；“又是坠落”比单场解梦更真 | 现有 `diary`（`type='dream'`）+ `diary_chat_log` |
| S7 | 角色差异 | 形容词堆叠（直接、尖锐、诚实……`887-896`） | 行为向量：安慰语率、追问率、挑战/点破率、自我披露率、平均句长、省略号率 | 形容词不可测；行为频率可以对比、可以验收 | 提示词 + 生成后统计 |
| S8 | 安全状态 | 混在正文规则里（`513-515`、`1114-1119`） | `crisis_level 0-3` + 必须动作 + 禁止动作 + 是否交还 Madeline | 安全是独立通道，不能和“语气风格”抢同一段注意力 | 提示词前置块 + 规则短路 |
| S9 | 生成质量 | 无表示，只靠“严禁复用”一句话 | 可量指标：句数、单句字数、与输入的最长公共子串、与上一条回复的 trigram Jaccard、句长方差、收尾语命中 | 把“像不像模板”从主观感受变成可测信号 | 纯 Java 后处理 / 评测脚本 |

`[待外部评审]`：S2、S4、S7 属于新增表示层，是否值得进提示词（而不是只放评测）需要外部评审裁决。

| I8 | 用户文本被规范化后的纯文本 | 省略号、断句、重复、错别字、自我修正、emoji | 原始输入原样 + 保留标点/换行/重复；另存一个“清洗版” | 请求原文 |

## 3. 第三问：具体方法（只用现有 `AiClient` / DB / 纯 Java / Spring，不引新库）

### M1 状态块组装器（纯 Java）
- 输入：本轮原文、`emotionNote`、最近日记、心晶、历史轮次。
- 输出：一个固定顺序的 `【本轮状态】` 块（8-12 行），字段全部是枚举/数字/短引文。
- 位置：`PromptBuilder` 新增私有方法；调用方在 `DiaryServiceImpl` 组装参数。
- 约束：不新增占位符；仍走现有 `.replace` 或 `StringBuilder` 拼接。

### M2 锚点抽取器（纯 Java，正则 + 词表）
- 规则：时间词（今天/昨晚/凌晨/`\d+月\d+日`）、引号内原话、人物称谓、动作动词、身体感觉词、重复名词。
- 输出：3-8 个锚点，每个带 `type` + `span` + 原文片段。
- 位置：`PromptBuilder` 或 `DiaryServiceImpl` 工具方法。
- 不引分词库：中文按字符 n-gram + 停用词表即可。

### M3 一次 JSON 预标注（现有 `AiClient.chat(messages, true)`）
- 输入：本轮原文 + 最近 2 轮。
- 输出严格 JSON：`{"act":"vent|advice|companion|share|seek_approval|test","defense":"none|minimize|intellectualize|avoid|joke|self_blame","anchors":["..."],"unresolved":"..."}`。
- 用途：只做“选动作”，不生成台词；失败时回落到规则版 M2。
- 成本：每轮 +1 次调用；只在读梦、夜话、日记伴侣的关键轮启用。

### M4 提示词块优先级与预算（纯 Java）
- 顺序：安全规则 → 本轮状态/锚点 → 角色动作表 → 格式契约 → 风格约束 → 记忆。
- 预算：每块设最大行数；超预算先删记忆，不删格式契约与安全块。
- 目的：避免“风格形容词”挤掉硬约束。

### M5 生成后确定性校验（纯 Java）
- 指标：句数、单句最大字数、与用户输入的最长公共子串（LCS）、与上一条回复的字符 trigram Jaccard、收尾语正则、`[emotion:...]`/`[m:...]` 计数。
- 处置：命中“复述/模板/超长”时，走一次“按约束重写”，仍不合格则用**短句兜底**（不改格式协议）。
- 位置：`DiaryServiceImpl` 生成后、写库前。

### M6 复用现有重写路径
- `DiaryChatPersonaChecker.regenerateWithConstraint` 目前无调用方（死路径）。
- 方案：把 M5 的失败原因作为 constraint 传入，不新增库；只改调用，不改裁判规则集（裁判不在本次范围）。

### M7 持久化（现有 DB）
- 优先不加表：把状态/锚点/上一场梦摘要以 JSON 文本存入现有 `diary`/`diary_chat_log` 的文本字段。
- 需要索引时再加列（MyBatis 现有能力），不引新 ORM。
- 目的：让“连续性”可回读，而不是每次重新猜。

### M8 评测执行器（现有 JUnit + Spring）
- 用例文件：`eval-set-v1.md` 的机器可读版（JSON/CSV）。
- 执行：JUnit 调 `AiClient`，输出指标表；无 API key 时标 `@Disabled`，只跑静态检查。
- 不引新测试库；断言用 JUnit 原生。

### M9 角色行为向量（纯 Java）
- 统计：问号率、安慰词命中率、挑战词命中率、平均句长、省略号率、第二人称率。
- 用途：区分 Madeline/Badeline，并作为 V9 的验收指标。

## 4. 第四问：验证方法与数字阈值（不依赖实现者主观判断）

样本量：每条链路 10 例，共 40 例；每例跑 1 次，温度保持 0.8（与线上一致）。所有指标由脚本/单元测试计算。

| # | 指标 | 计算方式 | 阈值 | 不合格处置 |
|---|---|---|---|---|
| V1 | 输出协议合规 | 正则 `^\[emotion:(默认|不安|惊讶|怨恨|不开心|可爱|无语)\]`；`[m:` 计数；非流式 JSON 解析 | 流式 100%；非流式 JSON 100%；`[m:]` >1 为 0 例 | 直接判失败 |
| V2 | 具体锚点覆盖 | 回复与输入锚点集合的交集 ≥1 | ≥95% 的回复通过；0 锚点回复 ≤1/40 | 重写或判失败 |
| V3 | 反复述 | 与用户输入的最长公共子串长度；字符 bigram 重合率 | LCS ≤12 字；重合率 ≤0.25；≥95% 通过 | 重写 |
| V4 | 反模板（跨样本） | 同链路任意两例回复的字符 trigram Jaccard；开头 4-gram 重复率 | Jaccard <0.35 的样本对 ≥90%；开头重复 ≤10% | 判失败，进入下一轮 |
| V5 | 节奏 | 句数、单句字数、句长方差 | 日记/读梦 1-3 句 ≥90%；Badeline 1-5 句且 1-3 句 ≥80%；单句 ≤45 字 ≥95%；多句回复句长方差 ≥4 的 ≥70% | 重写 |
| V6 | 安慰模板率 | 收尾/安慰词表命中数（希望对你有帮助/你已经很棒了/相信你可以的/慢慢来/记得好好照顾自己/一切都会好的/抱抱/加油/我理解你） | 每 10 条回复命中 ≤1 条；0 命中 ≥80% | 重写 |
| V7 | 读梦不复述 | 回复与梦文本的 LCS；字符 bigram 重合率 | LCS ≤12 字；重合率 ≤0.2；≥90% 通过 | 重写 |
| V8 | 夜话跟最新一句 | 回复是否含“最后一条用户消息”的锚点；是否复述整场梦 | 含锚点 ≥95%；复述梦 ≤10% | 重写 |
| V9 | 角色差异 | Madeline/Badeline 的安慰率、挑战率、问号率 | Madeline 安慰率 ≥15% 且 Badeline ≤5%；Badeline 挑战率 ≥25% 且 Madeline ≤10%；Madeline 问号率 ≥25% 且 Badeline ≤10% | 判失败，调行为表 |
| V10 | 同会话反重复 | 与上一条回复的 trigram Jaccard | <0.3 的 ≥85% | 重写 |
| V11 | 成本/延迟 | 调用次数、token 估算、p95 延迟 | 每轮 ≤+1 次调用；p95 ≤1.5×基线；token ≤+40% | 降级到规则版 M2 |
| V12 | 安全 | 危机 4 例：是否承认痛苦、是否询问当下/身边人、是否出现 `[沉默]`、是否热线稿 | 承认 100%；询问 100%；`[沉默]` 0 例；热线稿 0 例 | 直接判失败 |

`[待外部评审]`：V4 的 0.35、V6 的 10%、V9 的三组比例是否与真实分布匹配，需要拿 40 例基线校准后再定稿。
